## 一、这个网站是什么

这是 **REOG 的个人实验室**。它不是作品展板，也不是流量站，而是一个公开的工作笔记本：我在做什么、怎么想、哪里踩了坑，都会尽量写清楚。

我给它定了三条底线：

- **有用**：每篇文章至少解决一个具体问题，或者提供一个可复用的方法。
- **真实**：只写亲身实践过的东西，不转述、不凑数。
- **简短**：能用 800 字说清楚的，不写 2000 字。

## 三、这个站是怎么搭起来的

整个站由三个部分构成，流程很简单：

1. **Astro**：负责生成页面。它输出的是纯静态网页，加载快、维护成本低。
2. **GitHub**：存放全部源码与文章。每次修改都有记录，随时可以回退。
3. **Vercel**：监听 GitHub 的变化，一有新提交就自动重新部署。

所以我发布一篇文章的全过程只有三步：**写 Markdown → 提交 → 等待自动上线**。没有服务器要管，也没有数据库要备份。工具越少，出问题的地方就越少。

## 四、第一篇笔记：一个可复用的笔记模板

既然要长期写作，第一件事就是解决"每次从空白开始"的消耗。我用的是下面这个五段式结构，几乎适用于所有技术与实践类笔记：

1. **问题**：我想解决什么？一句话说清楚。
2. **背景**：现状是什么？有哪些限制条件？
3. **方案**：我最终怎么做的？为什么选它而不是别的？
4. **结果**：效果如何？尽量用事实或对比说明。
5. **复盘**：下次会怎么改进？有哪些没解决的遗留问题？

这个结构有两个好处。

**第一，它逼着你先想清楚再动笔。** 很多笔记写不下去，不是文笔问题，而是"问题"这一栏根本没想明白。

**第二，它让半年后的自己也能看懂。** 记忆会衰减，但"问题—方案—结果"这条线索不会。

### 可以直接复制的模板

```md
## 问题
（一句话）

## 背景
（现状与限制）

## 方案
（做法与理由）

## 结果
（事实与对比）

## 复盘
（改进与遗留）
```
